# BindWitness v0.1.1: Native Linux AMD64 Validation & Release

This compatibility milestone adds native Linux AMD64 validation and release
packaging alongside ARM64. It preserves the standard-library Go runtime,
explicit provider contracts and conservative evidence semantics.

- Four native validation jobs cover AMD64 and ARM64 in pinned Debian Bookworm
  (glibc 2.36) and Trixie (glibc 2.41) containers. Other architecture/glibc
  combinations remain unresolved. Ubuntu runner selection does not imply
  support for the runner's native Ubuntu userspace.
- Both lazy binding and explicit `LD_BIND_NOW=1` profiles check correct and wrong
  providers with the same `result=12` fixture output. Reports retain the explicit
  linker profile and raw evidence. Binding coverage is not function execution
  coverage or a call count; eager binding is never enabled automatically.
- Native, offline, comparison, cancellation, identity and CPython/zlib checks
  share the existing validation scripts. Bookworm checks two upstream zlib
  installations on each architecture, distinguishing provider and artifact changes.
- AMD64 and ARM64 archives come from their native Bookworm validation jobs in
  the same workflow run. Packaging checks saved binary version and SHA-256,
  ELF machine and extracted binary equality; a single `SHA256SUMS` covers both
  archives. No binary is rebuilt in
  the release job.
- A runnable AMD64 GitHub Actions example downloads and verifies the published
  binary, checks an explicit required provider contract and retains the JSON
  report when the CI gate fails.

All four native combinations passed in
[run 37236935579](https://github.com/0then0/bindwitness/actions/runs/37236935579)
for revision `6a5cb3c09aa0a0aa7facf8758cd81a01da02ede1`. Ordinary source builds
now enable AMD64 capture. Publication still requires successful completion of
the entire matrix in the release workflow's own run. These notes prepare a
future release; current evidence is recorded in [the validation guide](../validation.md).

After publication, download `bindwitness-0.1.1-linux-amd64.tar.gz` or
`bindwitness-0.1.1-linux-arm64.tar.gz` and `SHA256SUMS`. Verify the selected
archive's checksum before extraction. Each archive includes the Apache-2.0
license, README, documentation, icon and JSON schemas.

Capture scope remains one controlled executable lifetime in the base linker
namespace, with immutable artifacts and the existing unload/reload and identity
limitations. A proven provider violation remains FAIL alongside independent
capture issues; insufficient evidence remains UNRESOLVED. Workload exit status
is recorded separately from the binding verdict.

Offline checks also apply the platform boundary to saved executable and observed
binding identities in older reports. Unsupported ELF32/x32 or foreign-machine
evidence remains UNRESOLVED while a proven provider violation retains FAIL.
